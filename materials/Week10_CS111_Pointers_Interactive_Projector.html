Lockers and a note

Think about it

Given a locker number, can you get the book?
  • The number is not the book.
  • With the number you can find the book.
  • You can even replace the book inside!

RAM is a long row of numbered boxes

Two facts about every variable

Value: what is stored → age holds 19Address: where it is stored → age is at 1000
Real addresses look like 0x7ffd5e8c. We use small numbers (1000, 1004…) so we can trace easily.

The address-of operator &

int x = 25;
cout << x  << endl;   // value
cout << &x << endl;   // address
& reads as “address of”. &x = the address of x.

Sample output

25 0x7ffd5e8c
  • First line: the value inside x.
  • Second line: where x lives (hexadecimal).
The address can be different every time you run the program.

What is a pointer?

A pointer is a variable that stores the memory address of another variable.
stores an addresshas its own typehas its own address too

Picture it

p holds 1000 = the address of x. We say: “p points to x.”

Declaring pointers

int*    p;   // pointer to int
double* d;   // pointer to double
char*   c;   // pointer to char
Syntax: type* name; — the type says what kind of box it points to.

Read it right-to-left

int* p → “p is a pointer to an int.”
Trap: int* p, q; → only p is a pointer, q is a plain int. Declare one pointer per line.

Aim at a variable

int x = 25;
int* p = &x;
Safe ✔ p holds a real address.

Aim at nothing

int* p = nullptr;
Safe ✔ clearly “empty”, and we can test for it.

Uninitialized

int* p;  // garbage!
Dangerous ✘ holds a random address.
Rule: every pointer starts either pointing to a real variable or as nullptr.

The dereference operator *

int x = 25;
int* p = &x;
cout << p  << endl;  // 1000 (address)
cout << *p << endl;  // 25   (value)
* reads as “value at”. *p = the value at the address stored in p.

What prints?

nullptr: points nowhere

int* p = nullptr;

if (p != nullptr) {
    cout << *p;
} else {
    cout << "p points nowhere";
}

Why check?

  • nullptr means “no address”.
  • *p on nullptr crashes the program.
  • Check before you dereference.
Habit: initialize → check → use.

Missing *

p = 40;   // WRONG
*p = 40;  // RIGHT
p = 40 changes the address, not the value.

Type mismatch

double d = 2.5;
int* p = &d; // ERROR
Pointer type must match the variable type.

Uninitialized

int* p;
*p = 5;  // CRASH
Always initialize pointers first.

Warm-up: what does *p mean? What does &x mean?

int a[5] in memory — no gaps

Spot the pattern

Each int takes 4 bytesNext address = previous + 4
If a[0] is at 2000, where is a[3]? → 2000 + 3 × 4 = 2012

The array name is an address

int a[5] = {10, 20, 30, 40, 50};
cout << a     << endl;  // 2000
cout << &a[0] << endl;  // 2000
cout << *a    << endl;  // 10
So we can write int* p = a; — no & needed.

Pointer arithmetic

The rule

  • p + 1 → next element, not next byte.
  • It moves by sizeof(type).
  • int*: +4 · double*: +8 · char*: +1
Address of p + k = p + k × sizeof(int)

Traverse with a pointer

int a[4] = {3, 8, 1, 6};
int sum = 0;
for (int* q = a; q < a + 4; q++) {
    sum += *q;
}
cout << sum;     // 18

Read the loop header

1

Start: q = a

q points to the first element.

2

Test: q < a + 4

Stop at one-past-the-end.

3

Step: q++

Move to the next element.

4

Body: sum += *q

Add the value q points to.

Index style

for (int i = 0; i < n; i++)
    cout << a[i] << " ";
Counter i moves; the array stays put.

Pointer style

for (int* p = a; p < a + n; p++)
    cout << *p << " ";
The pointer p itself moves along the array.
Same output: 3 8 1 6 — choose the style that is clearest to you.

Subtracting pointers

int a[6] = {4, 9, 2, 7, 5, 1};
int* p = &a[1];
int* q = &a[4];
cout << q - p;    // 3
cout << *q - *p;  // 5 - 9 = -4

What it means

  • q - p = number of elements between them.
  • Not bytes: (2016 − 2004) ÷ 4 = 3.
  • *q - *p subtracts the values.
Turn a pointer back into an index: p - a

Danger: out of bounds

int a[4] = {3, 8, 1, 6};
int* end = a + 4;   // OK: one past end
cout << *end;       // ✘ undefined!
cout << *(a + 7);   // ✘ undefined!

Safe zone

  • a + 0 … a + 3 → safe to dereference.
  • a + 4 → only to compare (loop end).
  • Anything else → undefined behaviour: garbage or crash.
C++ does not check bounds for you.

Moving the array

int a[3] = {1,2,3};
a++;  // ERROR
Use a separate pointer: int* p = a; p++;

Missing ( )

*p + 1   // value+1
*(p + 1) // next one
Use parentheses to move first.

<= instead of <

q <= a + 4  // WRONG
q <  a + 4  // RIGHT
<= reads one element past the end.

Functions that change your variables

Pass an address instead of a copy, and a function can update the caller’s data: swap, many results, arrays.

Value vs addressswap()Output parametersArrays to functions
1

Why copies fail

Pass by value gives the function a copy.

2

Pass the address

Use & at the call and * inside.

3

Many results & arrays

Output parameters and array processing.

Big idea: an address lets a function reach the caller’s variable.

Recall: pass by value

void addTen(int n) {
    n = n + 10;
}
int main() {
    int score = 50;
    addTen(score);
    cout << score;   // ?
}

Predict

Does it print 50 or 60?
50 — the function changed a copy
Normal parameters receive a copy of the argument (pass by value). The original is safe — and unreachable.

The fix: send addresses

Three moves

1

Caller sends &x, &y

Addresses, not values.

2

Function receives int* a, int* b

Pointer parameters store them.

3

Uses *a, *b

Reaches the original x and y.

The function

void swapP(int* a, int* b) {
    int t = *a;
    *a = *b;
    *b = t;
}

The call

int x = 3, y = 8;
swapP(&x, &y);
cout << x << " " << y; // 8 3
& at the call · * inside the function.

Pass by value ✘

void addTen(int n) {
    n = n + 10;
}
addTen(score);    // still 50
Changes a copy only.

Pass by pointer ✔

void addTen(int* n) {
    *n = *n + 10;
}
addTen(&score);   // now 60
Changes the caller’s score.

Return two results

void minMax(const int* a, int n,
            int* mn, int* mx) {
    *mn = a[0];  *mx = a[0];
    for (int i = 1; i < n; i++) {
        if (a[i] < *mn) *mn = a[i];
        if (a[i] > *mx) *mx = a[i];
    }
}

The caller

int m[5] = {7, 2, 9, 4, 6};
int lo, hi;
minMax(m, 5, &lo, &hi);
// lo = 2, hi = 9
return gives back one value. Pointer parameters let a function hand back two or more.

Arrays are passed as pointers

  • The array name is an address → the function gets a pointer.
  • int arr[] and int* arr mean the same in a parameter list.
  • Changes inside change the caller’s array.
  • Always pass the size n too.

Example

void doubleAll(int* arr, int n) {
    for (int i = 0; i < n; i++)
        arr[i] = arr[i] * 2;
}
This is why the sorting functions in Week 09 could change the caller’s array!

Read-only: const pointers

int total(const int* arr, int n) {
    int s = 0;
    for (int i = 0; i < n; i++)
        s += arr[i];
    // arr[0] = 99;   ✘ compile error
    return s;
}

A promise to the caller

const int* = “I will only read.”
  • Protects the caller’s data.
  • The compiler blocks accidental writes.
  • Same idea as const int a[] in Week 09.

Tricky poll

void f(int* p) {
    p = nullptr;
}
int x = 5;
f(&x);
cout << x;
Look carefully: is there a * before p?

What prints?

f changed its own copy of the pointer, not *p. x stays 5.
